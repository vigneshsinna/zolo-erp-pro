# D01 — Active workflow binding

Base: `feature/ai-unified-input-clarification`, remote and local SHA `ee9be8cb3b42776e5f338d760b1940db8f497dca` (17 November 2026).

The chat controller previously always reached the provider. The PO tool used a request UUID as its thread and swallowed inaccessible task errors. The focused bare-PO test failed with HTTP 500 when provider calls were forbidden.

This change adds an actor/company/branch/FY/thread resolver and an opt-in router before generic chat. It reuses workflow persistence, correction evaluation, permission checks, gateway admission and chat storage. Receipt events serialize under the owned thread lock; identical turn retries reuse the response, while changed input conflicts. Cancellation changes draft state only. Multiple drafts require explicit selection. Read-only interruptions expose only read tools. PO tools now receive the authoritative chat thread and reject inaccessible task references.

Contract: `AI_CONVERSATION_ENABLED=false` by default. Conversation requests supply an owned `thread_id` and `client_turn_id`; cancellation also supplies `active_task_id` and `expected_task_revision`. The response adds `interaction_type` and `workflow`. No migration or ERP document writes.
