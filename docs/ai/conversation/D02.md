# D02 — Typed conversational corrections

Stacked on D01 (`9c8e1dd`). The missing interpreter was reproduced before implementation: three focused tests errored because `ConversationalSlotInterpreter` did not exist.

Fixed commands parse without a provider. Multi-slot replies reuse `TaskCorrectionService`; lines keep stable IDs, decimal text and unrelated values. Complex replies use a bounded, tool-free structured agent through `ApprovedModelGateway` and its existing credit meter. Only named queries and allowed field operations pass the parser boundary; model-supplied ERP IDs are rejected. Provider dispatch occurs outside the draft transaction so rejected output cannot roll back charges. Permission, expiry, revision and field-path checks precede draft application. A ready draft uses the existing proposal/preview engine; unchanged payload and source hashes reuse the proposal version. No action is approved or executed.
