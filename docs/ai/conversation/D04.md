# D04 — Purchase order terms parity

Stacked on D03 (`7e8b09e`). Normal purchase entry already supplies `paying_method` and `credit_days`. Supplier defaults already contain `purchase_defaults.payment_mode`; the domain stores credit days and the calculated terms date in `attributes_json`. Actual payments use `paying_method` only with a positive paid amount. These existing semantics are reused.

The AI schema/tool/requirements now carry commercial `payment_terms_type`, `credit_days` and a domain-derived `due_date`. Supplier defaults are scoped, visible as `erp_default`, and never overwrite explicit corrections. Cash requires zero days. Credit allows 0–3650 days. The preview and normal PO command call the same domain terms normalizer. Terms round-trip in purchase attributes, action receipt, open-order readback and print references. No migration is needed. Supplier terms/defaults participate in source freshness. Terms edits recompute the date and require a new proposal version.

Ordered status remains 4 and paid amount remains zero. The existing domain computes **payment_status 2 (Due)**, despite the legacy adapter's input value 1; this PR preserves the authoritative result. Cash terms never create a payment or GL entry. A PO print continues to omit a payable due-date label because an order is not yet a bill.
