# D05 — Conversation choices

Stacked on D04 (`7a5b15e`). The focused ordinal test initially errored because the response contained no `workflow.choices` (1 test, 3 assertions, 1 error).

Conversation choices now bind opaque option UUIDs, displayed order, field, task revision, actor, expiry and record fingerprints in existing workflow events. Ordinals select only from that set. Refresh, task edits, record changes and inactive/wrong-branch records invalidate selection. The server rechecks eligibility under a lock before creating a typed correction. Clicked options and spoken ordinals share the same path. Model output cannot supply choice records or ERP IDs.

Explicit directory requests invoke the existing `AiEntityOptionsController` query path with the authenticated request and verified active context. No second directory endpoint or search engine is added. Existing resolution candidates feed the same choice binder. Unit/product searches require an unambiguous draft line; selecting a new product does not invent a quantity.
