Those are configuration-assumption failures, not proof of a DELTA regression. Billing service, tests, both configuration files and `phpunit.ai.xml` have identical Git blob IDs to inspected `ee9be8c`; the manifest records them. This task does not repair or certify prior billing/T07 work.

The earlier pack's T00–T11 release evidence is not supplied as completed. In particular generic master tax/HSN fallback outside conversational tasks, telemetry/credit release acceptance, edge deployment and staging/production gates remain prerequisites. The deterministic conversation uses existing task/event/proposal correlation; this report does not claim a separate `ai_runs` lifecycle for every deterministic turn or replace T07 observability.

No authorized safe staging provider run, real microphone transcription, simultaneous browser-session workflow race, or production smoke was performed. Final release acceptance must resolve these gaps and the failing existing suite. `AI_CONVERSATION_ENABLED` remains **false by default**; no production flags changed.

Risks: the parse-only model remains probabilistic and server validated; existing expiry, scoping, permissions, revisions, signed versions and human approval stay authoritative. UOM freshness conservatively hashes and locks all units within one company: unrelated unit changes can require a fresh preview, and large unit catalogs can increase contention. This ceiling is documented at the implementation. No posted financial record is edited by conversation.

Rollback: leave `AI_CONVERSATION_ENABLED=false`, or disable it if a separately approved canary enabled it. Revert task commits in reverse stack order if code rollback is needed. There is no DELTA migration to reverse. Preserve created masters, immutable approvals/execution receipts and ERP documents; do not delete financial/audit records. The isolated scratch server/schemas contain fixtures only and can be stopped/removed independently after evidence retention.
